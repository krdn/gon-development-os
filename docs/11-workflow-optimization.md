2026-11-09, `b8194f9ddefb2e0d3168f93cda6eb7878fb7017a`의 매뉴얼·실행 양식·초보자 안내·생성기·CI를 대조했다. 요청은 전체 공정의 중복·부족한 부분을 고치고 Orca 지원과 불필요한 절차를 제거하는 것이다.

## 적용 원칙과 호환성

- 기존 문서·승인·보류를 다시 만들거나 소급 변경하지 않는다. 기존 프로젝트는 새 양식과 필요한 절만 비교·병합한다.
- 기획·첫 기능·전달 묶음은 예시다. 기존에 단계별 검토를 합의했다면 그 경계를 유지한다. 판단 위임은 실제 답변의 해당 범위만 적용하고 사용자 직접 수용과 구분한다.
- 작은 수정은 현재 상태 확인 → 변경 → 관련 확인 → 기록으로 마친다. 설계·조사·협업 문서를 일괄 생성하지 않는다.
- 초보자 안내는 사용자가 한 단계씩 배우는 실습이다. 전체 실행 계약으로 작업을 맡겼다면 실습 요청문을 매번 다시 입력할 필요가 없다.
- Orca 지원 제거와 실행 계약의 번호 변경을 전달 단위의 호환성 변경으로 보아 2.0.0으로 올렸다. 실행 계약과 STATE에 2.0.0 버전을 표시하고, 구 05→현 06 등 번호 대응을 실행 계약에 기록했다. 과거 단계 번호는 당시 문서·이름·실제 결과와 대조한다.
- `archive/`, 과거 `evidence/`, CHANGELOG와 `skills.lock`에 고정된 전문 스킬 사본은 역사·원본 무결성을 위해 보존한다. 남은 Orca 문자열은 현재 지원 경로가 아니다. 스킬 원본·전역 설치본·앱 설정은 이번 변경 대상이 아니다.

## 외부 리뷰 반영

Claude Opus 5.5/high의 첫 리뷰는 P2 5건·P3 7건을 지적했다. 실제 반환 모델은 `claude-opus-5-5`로 확인했다. 남은 PRODUCT 지시, 계약 버전·번호 대응, 단일 단계 요청 범위, 조건 없는 구현 지시, 검토 지점의 확정 주체, 인계 쓰기 책임과 날짜·기록 표현을 보완했다. 검토 지점은 기존 사용자 요청·답변·명시적 위임을 먼저 적용하며 예시를 자동 승인으로 사용하지 않는다.

최종 매뉴얼 빌드 전에 PASS를 쓰는 순서도 고쳤다. 현재 기록은 RUNNING으로 유지한 채 생성·검증하고, 최종 ZIP에 확정 기록을 넣어 무결성을 확인한 뒤 PASS 기록을 원자적으로 교체한다. 하위 폴더의 과거 보고서보다 전체 빌드 상태·해시를 우선하도록 안내했다. 수정분 리뷰에서 남은 명세 이름과 공정 이름을 통일했고, ZIP 검사가 실패하면 전체 빌드 PASS 로그가 나오지 않도록 고쳤다. 마지막 실패는 수정 전 회귀 검사로 재현한 뒤 수정 후 통과를 확인했다. 세부 지적별 처리는 아래 검증 기록에 남긴다.

## 검증과 한계

빌드 오류는 외부 명령 실패를 주입해 재현했다. 수정 전 `test_failed_rebuild_invalidates_previous_pass`가 실패했고, 수정 후 관련 12개 검사가 통과했다. 사용자 편집 기획 사본은 실패 시에도 덮어쓰지 않는 검사를 함께 수행했다. 자동 동기화 뒤 실패한 실행을 재시도할 때는 마지막 동기화 해시를 보존해 생성기 자신의 변경을 사용자 편집으로 오인하지 않도록 했다. 이 재시도도 수정 전 실패·수정 후 통과를 확인했다.

전체 재생성, 81개 저장소·스킬 검사, 14개 Herdr 브라우저 검사, 흐름도 네 검증 단계와 산출물 무결성 검사가 통과했다. 매뉴얼 복사 버튼의 실제 클립보드 내용도 표시 요청문과 일치했다. 관리 매뉴얼 PDF는 45쪽·목차 29개, Herdr PDF는 각각 39쪽·전체 요청문 44개를 확인했다. 세부 결과와 외부 리뷰 지적 처리는 [검증 기록](../evidence/workflow-optimization.json)에 남겼다. 마지막 3건은 직접 수정·검증했으며, 수정 후 외부 PASS를 받은 것으로 표시하지 않는다. 과거 검증 기록은 이번 성공 근거로 사용하지 않는다.

이번 검증은 안내서·생성기·고정 스킬 테스트 범위다. 실제 Herdr 작업자의 전체 프로젝트 수행, 비용·소요시간 개선, 설치본 갱신, GitHub 업로드·CI, 운영 제품 배포는 별도다.
