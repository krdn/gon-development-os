# Herdr 문서 인수와 협업 시험

이번 작업은 제품 구현이 아니라 실행 문서를 실제 모델이 읽고 협업 결과를 회수할 수 있는지 확인하는 제한 시험이다. HERDR-PROJECT의 전체 개발 규칙보다 이 시험 범위가 우선한다.

## 주 모델 작업

1. HERDR-PROJECT.md, HERDR-OPERATIONS.md, docs/PROJECT-BRIEF.md, docs/PLAN.md, docs/STATE.md를 읽는다.
2. 입력·출력·제외 범위·실제 원본 부재·AC10·다음 개발 행동을 요약한다.
3. 현재 Herdr 내장 매뉴얼과 명령을 확인하고 **이 시험 공간 안에서 협업 모델 하나**를 보이는 분할 또는 이름 있는 탭으로 연다. 다른 프로젝트 세션을 사용하지 않는다.
4. 협업 모델은 `claude --dangerously-skip-permissions`로 실행하고 Claude Fable `claude-fable-5-1`, effort xhigh를 요청한다. 사용 불가/인증/정책 차단이면 그 결과를 기록하고 다른 모델로 대체하지 않는다. 요청한 모델과 관찰된 모델은 구분한다.
5. 협업 모델에게 docs/ai/tasks/P002.md의 독립 기술 질문만 전달한다. 첫 요청 수신·작업 상태·실제 결과 파일을 확인한다. 결과를 읽고 주 모델의 다음 행동에 반영한다.
6. docs/ai/results/pilot-intake.md에 읽은 파일, 범위 요약, 협업 terminal/pane/tab, 선택/관찰 모델, 결과 경로, 채택한 내용, 차단·미검증, 다음 행동을 저장한다.
7. 대화에 `HERDR_OCR_INTAKE_DONE`과 결과 파일 경로를 보고하고 이 시험을 끝낸다. 제품 구현·설치·전역 설정 변경·GitHub/배포는 하지 않는다.

## 소유권과 제한

주 모델은 docs/ai/results/pilot-intake.md만 작성한다. 협업 모델은 docs/ai/results/pilot-worker.md만 작성한다. 이 저장소에는 다른 작성자가 있으므로 기준 문서나 기존 변경을 되돌리지 않는다. 협업 모델의 재위임은 금지한다. 결과가 없으면 있다고 보고하지 않는다. 같은 실패를 무한 반복하지 않는다.

주 모델 자신과 협업 모델은 대화형으로 유지한다. 협업 CLI의 도구 실행 승인은 실행 계약의 시작 옵션으로 생략한다. 계정 인증·OS 권한 오류는 실제 원인을 확인해 기록한다. 인증 화면에는 작업 지시문을 강제로 입력하지 않는다. blocked이면 원인을 읽고 그 지점에서 기록한다. 시험 결과를 저장한 뒤 대기하며 추가 제품 작업을 시작하지 않는다.
