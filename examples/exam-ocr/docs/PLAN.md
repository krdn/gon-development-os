# 구현과 협업 실행 계획

현재는 문서·Herdr 인수 시험 단계다. 제품 단계는 사용자가 README의 전체 개발 시작 요청을 보낸 뒤 수행한다.

| 순서 | 작업 | 담당과 소유권 | 선행/완료 조건 |
| --- | --- | --- | --- |
| P0 | 문서 읽기·협업 답변·결과 저장 | Herdr 주 모델: pilot-intake / 협업: pilot-worker | PILOT 계약, 실제 결과 파일 확인 |
| P1~P5 | 기존 문제·조사·결정·BRIEF를 읽고 불일치만 해소 | 주 모델, docs 기준 문서 | 아래 연구 문서 재사용, 사용자 승인 사실 창작 금지 |
| D1 | 환경·의존성 확인과 한 페이지 변환 가능성 점검 | 주 모델, 개발 환경 및 변환 시제품 | 버전 기록·합성 1장 PDF 열기/검색 |
| D2 | 합성 입력과 정답 전사·검사 사례 준비 | 협업 모델, tests/fixtures와 테스트 설계만 | D1 인터페이스 합의 후 병렬 가능 |
| D3 | 최소 CLI·입력 보호·변환·보고서 구현 | 주 모델, src 및 패키지 설정 | D1 결과, AC01~09 대응 |
| D4 | 정상/오류/재실행 검증과 수정 | 주 모델이 통합; 테스트 협업자는 지정 테스트 파일 | D2/D3, 실제 실패 수정·관련 재검사 |
| D5 | 적용 지침의 외부 리뷰 1회 | 지정 외부 모델, 읽기 전용 | 실제 변경·검사 결과, 반환 모델 확인 |
| D6 | 사용자 원본 수용 검사 | 주 모델 실행 + 사용자 원본/확인 | 원본 필요; 없으면 AC10 NOT_RUN |
| D7 | README·STATE·최종 결과 인계 | 주 모델 | 모든 필수 AC와 리뷰 해결 |

주 모델은 Astra를 초기 후보로, 독립 기술 쟁점에는 Fable을 후보로 삼는다. 사용 가능 여부와 실제 적용 근거는 실행 시 확인한다. 후보 불가 시 같은 작업을 임의 모델로 바꾸지 않는다. Tesseract는 제품 OCR 엔진이며 협업 LLM과 다른 구성요소다.

한 번에 같은 파일의 작성자는 한 명이다. 작업자가 둘이면 구현 인터페이스를 먼저 저장하고 테스트 작업자는 src를 고치지 않는다. 새 작업 계약에는 기준 revision 또는 문서 해시, 허용 파일, 결과 파일을 적는다. 의존 작업을 동시에 시작하지 않는다.

범위를 바꾸는 질문은 검색형 PDF와 재조판 PDF의 차이, 실제 원본의 사용 범위, 외부 처리 필요성에 한정한다. 일반적인 기술 선택은 근거와 시험 결과로 주 모델이 결정한다. 원본이 없더라도 합성 개발 작업은 계속할 수 있다.
