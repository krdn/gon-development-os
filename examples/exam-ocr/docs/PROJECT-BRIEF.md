# 시험문제지 OCR PDF 개발 기준

버전 1.0 · 2026년 11월 3일 · 상태: 실행용 설계 초안, 사용자 원본 미제공.

사용자 확정 요구 U01: 시험문제지를 OCR 변환하여 PDF로 만드는 프로젝트 문서를 작성하고 Herdr에서 작동 여부를 확인한다. 아래 제품 세부 범위는 이를 구체화한 AI 설계 결정이며 별도의 사용자 승인 사실을 주장하지 않는다.

## 결과와 사용자 흐름

로컬 CLI에서 PDF 한 개 또는 순서를 지정한 이미지 목록을 입력한다. 입력을 검사하고 한영 OCR을 수행한 뒤 검색 가능한 PDF, 페이지별 텍스트, 페이지별 처리 결과를 생성한다. 사용자는 PDF를 열어 원본 배치·페이지 순서와 문구 검색을 확인하고 검수 보고서의 의심 영역을 대조한다.

첫 범위는 인쇄된 한국어·영어 시험지다. 손글씨, 완전한 수식 전사, 표의 논리적 구조 복원, 읽기 순서의 완전성은 보장하지 않는다. 수식·표·그림은 원본 시각 내용을 유지하고 텍스트 인식 한계를 보고한다. 정답·해설을 생성하거나 잘린 문제를 추측해 복원하지 않는다.

## 요구사항과 수용 기준

| 요구 | 수용 기준 | 검사 |
| --- | --- | --- |
| R01 PDF 또는 순서 지정 JPG/PNG 입력 | AC01 입력 순서를 유지하고 처리할 페이지 수를 표시 | 3장 순서 지정 입력과 PDF 비교 |
| R02 원본 불변 | AC02 변환 전후 원본 SHA-256 일치; 입력=출력 경로 거부 | 해시와 거부 테스트 |
| R03 원본 배치 유지 | AC03 페이지 수·순서·문항 번호·선택지·수식·그림의 누락/잘림 없음 | 모든 합성 페이지와 실제 시험지 전 페이지 시각 대조 |
| R04 한국어·영어 검색형 PDF | AC04 깨끗한 합성 시험지의 사전 지정 10문구(한글 5·영어 5)가 출력 PDF 텍스트 추출과 뷰어 검색에서 모두 확인됨 | 원본과 독립적으로 만든 정답 텍스트 사용 |
| R05 페이지별 결과 | AC05 텍스트와 처리 보고서에 입력 페이지 번호·상태·오류·검수 필요가 대응됨 | PDF와 보고서 페이지 대조 |
| R06 불확실성 표시 | AC06 이미지에 존재하지 않는 문항·답을 추가하지 않고 빈 인식/저품질/복잡 영역의 미검증 상태 표시 | 흐림·빈 페이지·수식 포함 사례 |
| R07 오류 처리 | AC07 손상/암호 PDF·미지원 입력·실행 의존성 누락·시간 초과에서 한국어 오류와 비정상 종료; 성공 PDF를 남기지 않음 | 오류별 재현 |
| R08 재실행 보호 | AC08 기존 출력 덮어쓰기 기본 거부, 명시적 허용 때만 교체; 실패 시 이전 정상 출력 보존 | 2회 실행 및 중간 실패 |
| R09 로컬 처리 | AC09 변환 경로에 외부 OCR/LLM 호출 없음; 원문·인증값을 실행 로그에 노출하지 않음 | 코드·실행 경로 점검 |
| R10 실제 원본 수용 | AC10 사용자 시험지에서 페이지 보존 확인, 사용자 지정 검색 문구 확인, 사람이 확인한 정확도/오류 목록 기록 | 원본 미제공이면 NOT_RUN |
| R11 재현 가능한 인계 | AC11 새 환경 설치·샘플 실행·출력 확인·한계 설명을 README로 수행 가능 | 문서대로 재실행 |

AC04는 고정 합성 회귀 기준이며 모든 시험지의 100% OCR 정확도를 뜻하지 않는다. 실제 원본의 CER은 선택한 정답 전사 범위와 정규화 규칙을 공개하고 측정한다. 원본을 보기 전에 임의의 정확도 수치를 합격으로 선언하지 않는다.

## 입출력 계약

- 입력: PDF 파일 하나 또는 사용자가 지정한 순서의 JPG/PNG 파일 목록. 디렉터리 자동 정렬에 의존하지 않는다.
- 기본 언어: `kor+eng`. 언어팩 누락은 명시적 실패다.
- 출력: `<name>.searchable.pdf`, `<name>.txt`, `<name>.report.json`.
- 성공: 모든 페이지의 처리 여부가 보고되고 PDF를 열 수 있으며 필요한 AC를 만족한다.
- 부분 실패: 실패 페이지가 있으면 전체 성공으로 반환하지 않는다. 진단 자료만 별도 이름으로 보관한다.
- PDF/A 인증·문서 재조판·DOCX/HWP·웹 UI·계정·DB·GitHub/운영 배포는 첫 범위 밖이다.

## 권한과 완료

현재 문서 시험은 `PILOT.md`로 제한한다. 전체 개발 시작 후 허용 범위는 로컬 프로젝트 파일·가상환경·합성 데이터·테스트다. 시스템 패키지가 필요하면 적용 sudo/인증 규칙을 따른다. 이미 허용된 가역 작업은 반복 승인 없이 진행한다. 외부 업로드·과금·공개는 포함하지 않는다.

실제 원본이 없으면 도구와 합성 검증을 마칠 수 있지만 AC10은 NOT_RUN이고 프로젝트 전체는 `awaiting_user`다. 문서/Herdr 시험 완료와 제품 완료를 분리한다.
