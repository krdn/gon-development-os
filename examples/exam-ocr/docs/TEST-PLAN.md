# 시험문제지 OCR PDF 검증 계획

상태: 제품 검사는 모두 NOT_RUN. Herdr 문서 인수 시험과 분리한다.

## 합성 시험지

개발 시작 후 실제로 생성한다. 이 문서 작성 시 입력 이미지를 만들어 놓았다고 주장하지 않는다. 개인정보·실제 시험 문제를 복제하지 않고 아래 내용을 가진 독자적인 샘플을 만든다.

| 샘플 | 포함 내용 | 확인할 위험 |
| --- | --- | --- |
| S01 | 깨끗한 한글·영어 인쇄문, 문항 1~3과 선택지 | 검색·복사·한영 언어 |
| S02 | 2단 문항, 간단한 표·분수/지수·도형 | 누락·잘림·시각 배치, 텍스트 읽기 순서 한계 |
| S03 | 같은 샘플의 흐림·회전·빈 페이지 변형 | 인식 실패/검수 표시 |
| S04 | 순서 지정 3장, 손상 파일, 암호 PDF, 기존 출력 | 페이지 순서·오류·덮어쓰기 |

합성 입력의 정답 텍스트는 OCR 출력에서 역으로 만들지 않는다. AC04의 10개 문구는 샘플 생성 시 고정하고 OCR을 보기 전에 저장한다. 합성 검사를 통과시키려고 문구를 사후 변경하지 않는다.

## 수행 순서

1. 원본 SHA-256, 도구 버전, 실행 명령, 입력 종류와 페이지 수를 기록한다.
2. 결과 PDF를 실제로 열거나 렌더링한다. 원본과 같은 해상도로 렌더링해 페이지별로 배치·수식·그림을 비교한다. 뷰어 확인과 자동 렌더링 검사를 구분한다.
3. `pdftotext` 등 독립 추출기로 고정 문구를 검색한다. 가능하면 PDF 뷰어에서도 검색·선택·복사를 확인한다. 추출 성공만으로 모든 뷰어 호환성을 주장하지 않는다.
4. 원본 해시 일치, 페이지별 report 대응, 반복 실행 보호와 오류별 종료 상태를 확인한다.
5. 수식·표·선택지가 원본에 보존되는지 확인하고 OCR 텍스트 오인식을 품질 보고서에 남긴다.
6. 실제 원본이 제공되면 모든 페이지를 확인하고 사용자가 지정한 문구를 검색한다. 수기 전사 표본이 있을 때만 CER을 계산한다.

CER = (삽입 + 삭제 + 치환 문자 수) / 정답 문자 수. 정답이 빈 경우 계산하지 않는다. 한글 NFC 정규화와 공백·개행 처리 규칙을 결과에 명시하고 정답/예측에 동일하게 적용한다. 합성 점수를 실제 원본 점수로 대체하지 않는다.

## 기록

각 AC에 PASS, FAIL, NOT_RUN, UNKNOWN 중 하나와 입력 해시·대상 코드 버전·명령·실제 결과·증거 경로를 남긴다. 테스트는 잘못된 문서·암호/손상·언어팩 누락·중간 실패가 정상 PDF로 오인되는 것을 확인한다. 입력 크기·페이지 수 제한과 시간 제한은 실제 환경에서 정하고 문서화한다.

원본이 없거나 사용자가 육안 확인하지 않았다면 그 범위를 그대로 NOT_RUN으로 둔다. 필수 항목이 남은 제품은 완료로 표시하지 않는다.
