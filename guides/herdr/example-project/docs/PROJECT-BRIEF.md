# 개발 시작 문서 — 개인 할 일 앱 학습 예시

문서 버전: 예시 1 / 상태: 설명용 가상 합의 / 실제 승인일: 없음

실제 프로젝트에서는 사용자 확인 후 “개발 시작 승인”과 실제 날짜를 기록한다. 이 예시 파일만으로 실제 개발을 승인한 것으로 보지 않는다.

## 먼저 읽을 요약

개발 학습을 위해 같은 브라우저에서 할 일을 관리하는 작은 앱을 만든다. 첫 범위는 추가·완료/해제·삭제·새로고침 유지다. 로그인·서버·동기화는 제외한다. 첫 구현은 추가와 빈 입력 안내이며, 기술·저장 방식은 개발 준비에서 확인한다. 시작할 때 이 문서와 [STATE](STATE.md)를 읽는다.

## 사용자와 목표

개인 학습자 한 명. 실제 사용자가 다수라고 가정하지 않는다. 목적은 개발 과정과 확인 방법을 배우는 것이다. 근거는 [U01~U03](research/03-evidence.md), 선택 이유는 [D01~D03](research/04-decision.md)에 있다.

## 첫 범위와 완료 기준

| 요구 | 포함할 동작 | 직접 확인할 완료 기준 | 연결 결정 |
| --- | --- | --- | --- |
| R01 | 할 일 추가 | AC01: “우유 사기”를 넣고 추가하면 목록에 한 번 표시 | D02 |
| R02 | 완료·해제 | AC02: 완료 표시를 켜고 끌 수 있음 | D02 |
| R03 | 삭제 | AC03: 선택한 항목만 목록에서 사라짐 | D02 |
| R04 | 새로고침 유지 | AC04: 항목·완료 상태가 같은 브라우저 새로고침 후 일치 | D02·U02·U03 |
| R05 | 빈 입력 처리 | AC05: 공백만 넣으면 추가되지 않고 안내 표시 | D02 |

제외: 로그인, 사용자 계정, 여러 기기 동기화, 서버 API, 알림, 상용 배포. 브라우저 데이터 삭제 후 복구를 보장하지 않는다. 실제 저장 한계는 구현 전에 확인한다.

## 핵심 사용 흐름

앱 열기 → 할 일 입력 → 추가 → 완료 표시 → 새로고침 후 유지 확인 → 삭제. 목록이 비어 있을 때 안내도 확인한다.

## 데이터·기술·제약

데이터는 항목 식별자·내용·완료 여부다. 민감한 개인정보를 연습 데이터로 넣지 않는다. 기술과 저장 방식은 미정이다. 학습 예제 경로를 명시적으로 선택하면 React + TypeScript 프런트 구성을 후보로 삼을 수 있지만, 기존 프로젝트에 임의로 적용하지 않는다.

## 남은 미정과 시작 가능 범위

| 미정 | 담당·해결 시점 | 무엇을 막는가? |
| --- | --- | --- |
| 기술 선택 | 사용자와 개발 A, 환경 준비 전 | 환경 구성은 선택 후 진행 |
| 저장 API의 범위·삭제 조건 | 개발 A, 저장 구현 전 | R04 구현·완료 판정은 확인 전 보류 |

이 문서로 새 세션의 인계 요약과 기술 비교는 시작할 수 있다. 미정을 확정한 척하여 전체 구현으로 넘어가지 않는다.

## 첫 작업과 다음 요청

첫 작업: R01·R05. 실제로 입력·추가·빈 입력을 확인한 뒤 R02~R04를 잇는다.

새 개발 세션에 보낼 요청:

“이 문서와 STATE를 실제로 읽고, 목표·포함·제외·AC번호·미정·첫 작업을 요약해줘. 설명용 예시 상태이므로 실제 프로젝트의 문서와 사용자 승인을 먼저 확인해. 기술이 미정이면 후보를 설명하고 내 선택을 기다려. 아직 구현하지 마.”
