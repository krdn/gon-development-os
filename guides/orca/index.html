내일 같은 일을 이어서 함기존 세션 resume같은 프로젝트·같은 Codex 설정 홈에서 이름/ID 확인.

첫 출시 안의 수정·검증같은 개발 세션작은 구현·검증을 반복하고 관련 작업자에게 send.
첫 출시 완료 → 독립 새 기능새 세션·새 작업 묶음최신 문서·이슈에서 시작. 이전 결과를 인계.
대안만 따로 탐색필요하면 fork대화 분기이며 Git 브랜치/worktree 분리와 다름.
대화가 길어짐문서 저장 후 compact맥락 요약일 뿐 파일·GitHub·Run 상태 저장을 대신하지 않음.

근거: Codex 공식 명령 설명 · resume 동작 · 설치 Orca orchestration 가이드. “P5 후 새 개발 세션”은 이 안내서의 운영 권장 방식입니다.

오늘 멈추고 내일 재개하는 정확한 순서
  1. 현재 주 조정자에게 아래 “중단 전 저장” 요청을 보냅니다. 활성 작업자가 있으면 그대로 종료하지 말고 상태를 확인합니다.
  2. 기록이 저장되고 종료 가능한 상태이면 현재 Codex에 /quit를 한 줄로 입력합니다.
  3. 다음에 Orca에서 같은 작업공간·같은 실행 환경을 엽니다. 기존 Codex 탭이 살아 있다면 그 탭을 계속 씁니다.
  4. 종료된 경우 일반 터미널에서 아래 resume 명령으로 세션 목록을 열고 프로젝트-기획 또는 프로젝트-개발 이름과 경로를 확인해 선택합니다. 작업자 대화를 잘못 선택하지 않습니다.
  5. 재개 요청을 보냅니다. Codex 대화 복구와 Orca Run 연결은 별도입니다. 이전 조정자가 살아 있다면 같은 Run을 다른 조정자가 빼앗아 관리하지 않습니다.

/new · /fork · /compact를 언제 쓰나요?

/new는 현재 CLI 안에서 새 대화를 시작합니다. /fork는 이전 대화 맥락을 가진 별도 대화로 분기합니다. 둘 다 Git 변경을 자동 분리하지 않습니다. /compact는 긴 대화를 요약합니다. 작업자가 진행 중인 주 조정자에서는 대화를 바꾸기 전에 조정 상태를 확인하세요.

기획에서 개발로 넘어갈 때는 새 탭과 명확한 이름을 써서 역할을 구분하는 편을 권합니다. fork는 별도 대안 검토용이며 필수 단계가 아닙니다.

세션 새 기획 세션 1개

1. 이 순서로 진행하세요

  1. Orca의 Add a project(프로젝트 추가)를 엽니다. 새로 시작하면 Create new project → 프로젝트 이름과 Parent folder(상위 폴더) → Create project 순서로 만듭니다. 기존 폴더라면 Browse folder → 해당 폴더 선택을 사용합니다. Git이 없는 폴더에는 Open as Folder를 선택해 기존 상태를 유지할 수 있습니다.
  2. 기존 GitHub 저장소에서 시작한다면 Add a project → Clone from URL → GitHub 저장소 URL과 Parent folder → Clone을 선택합니다. 이미 복제해 둔 폴더가 있다면 다시 복제하지 말고 Browse folder로 엽니다. 새로 만든 Orca 프로젝트는 로컬 Git을 준비할 수 있지만 GitHub 원격 업로드는 G1에서 별도로 합니다.
  3. Settings(설정) → Agents → Choose per agent에서 Codex의 시작 방식을 Terminal로 선택합니다. Terminal은 Codex 자체 CLI를 쓰는 선택입니다. 전체 에이전트 기본값을 바꾸기보다 Codex 항목의 선택을 확인하세요. 설치 스킬은 이 구분을 Chat | CLI라고도 설명합니다. 새 Codex 탭을 열거나 아래 명령으로 주 조정자 CLI를 실행합니다.
