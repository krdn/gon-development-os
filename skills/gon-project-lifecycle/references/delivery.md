# 검토·전달·인수인계

## 완료 경계에서 검토한다

다중 파일 새 기능·아키텍처 변경 또는 재현 가능한 버그는 적용 규칙에 맞춰 커밋/완료 직전에 한 번 독립 검토를 수행한다. 단순 문서·설정 변경에는 자동으로 외부 호출을 붙이지 않는다.

현재 환경의 리뷰 지침·실행기·중앙 설정을 확인하고, 요구·관련 diff·검증 결과만 비밀값 없이 전달한다. 모델/effort는 사용자 지정과 유효 정책을 보존한다. 실제 응답·반환 모델을 확인하고 호출 실패를 리뷰 통과로 바꾸지 않는다. 구현자의 자기 점검은 독립 승인과 구분한다.

지적은 코드·재현 결과로 수용하거나 기각한다. 수정했다면 수정분과 관련 동작만 다시 확인하고 무제한 리뷰 루프를 만들지 않는다. 미해결 필수 지적은 그대로 남긴다.

## 요청받은 전달 단계까지 수행한다

기존 branch·CI/CD·저장소 정책을 따른다. 사용자가 `커밋·배포`를 요청했다면 범위 내 구현, 검증, 커밋/PR, 필수 CI·리뷰, 허용된 merge, 배포, 실제 환경 확인까지 이어간다. 이미 주어진 권한을 되묻지 않는다. 권한이 부족한 마지막 행동은 diff·PR·배포 대상·검증 결과를 구체화한 뒤 확인한다.

기존 배포 경로에 필요한 push·PR·merge는 현재 요청과 프로젝트 정책이 허용하는 범위에서 수행한다. 강제 push·보호 규칙 우회는 통상 배포 요청에 포함하지 않는다. 작업 관련 파일·변경 구간만 stage하고 staged diff를 확인한다. 기존 미커밋 변경 중 이번 요청에 속하지 않는 부분과 비밀값은 커밋에 포함하지 않는다.

아래 단계는 각각 별도로 확인한다. 환경이 제공하는 범위만 수행하고 미실행 상태를 밝힌다.

| 단계 | 확인할 근거 |
| --- | --- |
| 구현 | 요청한 동작과 관련 diff·제품 검사 |
| 커밋/PR | 실제 SHA·PR URL·범위 |
| 통합 | 해당 revision의 필수 CI/리뷰와 실제 merge |
| 배포 | 대상 환경·배포 revision·완료 결과 |
| 운영 확인 | 상태 점검과 요청에 관련된 실제 사용자/API 흐름 |

로컬 PASS를 운영 성공으로 확장하지 않는다. GitHub Actions YAML만으로 branch 보호가 활성화됐다고 주장하지 않는다. 배포는 실제 호스트·프로젝트·context를 확인하고 기존 롤백 경로를 따른다. `ACCEPT` 판정은 배포·메시지 전송 권한을 추가하지 않는다.

현재 세션에서 필수 CI·배포 결과를 기다려 확인하는 것은 전달 절차에 포함된다. 외부 승인 등으로 멈춘다면 현재 결과, 멈춘 단계, 필요한 행동을 구분한다. 세션 밖의 지속 감시·자동화는 사용자가 요청한 경우에만 구성한다.

## 인수인계는 다음 실행에 필요한 만큼 쓴다

기존 STATE 또는 사용자가 지정한 문서에 아래를 남긴다. 별도 HANDOFF는 필요하거나 요청됐을 때만 만든다.

- 목표와 확정된 범위, 현재 branch/revision·작업 경로.
- 완료한 동작과 실제 검증·증거, 아직 확인하지 못한 환경.
- 남은 문제와 실패한 접근, 다음 실행 가능한 행동.
- 관련 문서·PR/배포 링크, 현재 권한 범위.

재사용 가능한 개선점을 발견하면 구체적인 실패와 수정안을 제시한다. 프로젝트 수행을 이유로 전역 스킬·모델 설정·메모리를 임의로 고치지 않는다.
