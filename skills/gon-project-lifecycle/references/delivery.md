# 검토·전달·인수인계

## 완료 경계에서 검토한다

다중 파일 새 기능·아키텍처 변경 또는 재현 가능한 버그는 적용 규칙에 맞춰 커밋/완료 직전에 한 번 독립 검토를 수행한다. 단순 문서·설정 변경에는 자동으로 외부 호출을 붙이지 않는다.

외부 리뷰가 별도 단계로 정해졌다면 그 구성 승인까지 구현 결과를 검토 대기로 전달하고 리뷰를 호출하지 않는다. [단계 검토 절차](stage-review.md)의 사용자 결과 수용과 외부 모델 검토는 서로 대체하지 않는다.

현재 환경의 리뷰 지침·실행기·중앙 설정을 확인하고, 요구·관련 diff·검증 결과만 비밀값 없이 전달한다. 모델/effort는 사용자 지정과 유효 정책을 보존한다. 실제 응답·반환 모델을 확인하고 호출 실패를 리뷰 통과로 바꾸지 않는다. 구현자의 자기 점검은 독립 승인과 구분한다.

지적은 코드·재현 결과로 수용하거나 기각한다. 수정했다면 수정분과 관련 동작만 다시 확인하고 무제한 리뷰 루프를 만들지 않는다. 미해결 필수 지적은 그대로 남긴다.

## 요청받은 전달 단계까지 수행한다

[GitHub 관리 절차](github-management.md)의 이슈·Project·PR 연결과 원격 재조회를 함께 수행한다. PR에는 관련 이슈, 요구와 결과, 검사 대상 SHA·실제 CI/로그·화면 증거, 미검증과 알려진 문제를 남긴다. PR 생성만으로 완료 처리하지 않는다.

기존 branch·CI/CD·저장소 정책을 따른다. 사용자가 `커밋·배포`를 요청했다면 범위 내 구현, 검증, 커밋/PR, 필수 CI·리뷰, 허용된 merge, 배포, 실제 환경 확인까지 이어간다. 이미 주어진 권한을 되묻지 않는다. 권한이 부족한 마지막 행동은 diff·PR·배포 대상·검증 결과를 구체화한 뒤 확인한다.

기존 배포 경로에 필요한 push·PR·merge는 현재 요청과 프로젝트 정책이 허용하는 범위에서 수행한다. 강제 push·보호 규칙 우회는 통상 배포 요청에 포함하지 않는다. 작업 관련 파일·변경 구간만 stage하고 staged diff를 확인한다. 기존 미커밋 변경 중 이번 요청에 속하지 않는 부분과 비밀값은 커밋에 포함하지 않는다.

아래 단계는 각각 별도로 확인한다. 환경이 제공하는 범위만 수행하고 미실행 상태를 밝힌다.

| 단계 | 확인할 근거 |
| --- | --- |
| 구현 | 요청한 동작과 관련 diff·제품 검사 |
| 커밋/PR | 실제 SHA·PR URL·범위 |
| 통합 | 해당 revision의 필수 CI/리뷰와 실제 merge |
| 배포 | 대상 환경·배포 revision·완료 결과 |
| 운영 확인 | 상태 점검과 요청에 관련된 실제 사용자/API 흐름 |

로컬 PASS를 운영 성공으로 확장하지 않는다. GitHub Actions YAML만으로 branch 보호가 활성화됐다고 주장하지 않는다. 배포는 실제 호스트·프로젝트·context를 확인하고 기존 롤백 경로를 따른다. `ACCEPT` 판정은 배포·메시지 전송 권한을 추가하지 않는다.

현재 세션에서 필수 CI·배포 결과를 기다려 확인하는 것은 전달 절차에 포함된다. 외부 승인 등으로 멈춘다면 현재 결과, 멈춘 단계, 필요한 행동을 구분한다. 세션 밖의 지속 감시·자동화는 사용자가 요청한 경우에만 구성한다.

정의된 단계의 결과는 산출물 revision·검사·미검증과 다음 구성안을 제시하고 사용자의 수용/수정 요청/보류를 기록한다. 수정 요청은 같은 단계에서 반영·재검증하고 다시 검토받는다. 결과 수용 전 다음 단계에 진입하지 않으며 CI/모델 PASS만으로 검토 대기를 완료로 바꾸지 않는다.

이슈의 수용 기준을 확인하고, 정의된 단계가 있으면 사용자 결과 수용(특정 작업의 명시적 판단 위임은 [별도 위임 기록](stage-review.md)과 조정자 판정)도 확인한 뒤 실제 프로젝트의 종료 기준에 맞춰 이슈를 닫고 Project를 Done으로 옮긴다. 배포까지 필요한 작업은 merge로 자동 종료되지 않게 미리 연결 방식을 정한다. 구현 이슈와 배포 이슈를 나누거나 종료 키워드 대신 참조 링크를 사용한다. 릴리스 발행은 별도 허용 범위를 따르고, 실제 태그/커밋·릴리스 노트·첨부물·배포 실행과 환경을 원격에서 확인한다. 실패한 배포는 Done으로 처리하지 않는다.

Actions 로그/artifact에는 보관 기한이 있으므로 장기 수용 근거는 비밀값을 제거한 요약·해시를 저장소 문서 또는 허용된 Release asset에 남긴다. 외부 배포 시스템이면 GitHub 이슈/PR/Release에 외부 실행·환경·revision과 결과를 연결한다. 기록용 Deployment 생성도 이벤트를 발생시킬 수 있으므로 기존 파이프라인이 만든 기록을 재사용한다.

## 인수인계는 다음 실행에 필요한 만큼 쓴다

기준 GitHub 이슈/PR와 저장소의 기존 STATE 또는 사용자가 지정한 문서에 아래를 남긴다. 로컬 요약에는 원격 URL·마지막 확인 시점을 둔다. 별도 HANDOFF는 필요하거나 요청됐을 때만 만든다.

- 목표와 확정된 범위, 현재 branch/revision·작업 경로.
- 완료한 동작과 실제 검증·증거, 아직 확인하지 못한 환경.
- 남은 문제와 실패한 접근, 다음 실행 가능한 행동.
- 관련 문서·PR/배포 링크, 현재 권한 범위.

1차 완료나 부분 전달은 이번 목표와 그 AC 결과, 제품 전체의 남은 조건을 나눠 기록한다. 남은 FAIL·NOT_RUN·UNKNOWN에는 영향을 받는 기능·다음 행동·담당(미정이면 미정)·재개 조건을 연결한다. 사용자가 나중으로 정한 일은 그 결정도 남기며 자동으로 다음 실행 목표에 넣지 않는다.

실행 중인 로컬 앱을 인계하면 주소·실제 호스트·프로세스 식별 정보·시작/중지 명령·데이터와 백업 위치를 비밀값 없이 필요한 만큼 남긴다. 마지막으로 확인한 동작과 시각을 기록하고, 세션·앱 종료 뒤에도 살아 있는지 확인하지 않았다면 지속 실행은 미검증으로 표시한다. 인계 때문에 상주 서비스나 자동 재시작을 임의로 설치하지 않는다.

재사용 가능한 개선점을 발견하면 구체적인 실패와 수정안을 제시한다. 프로젝트 수행을 이유로 전역 스킬·모델 설정·메모리를 임의로 고치지 않는다.
