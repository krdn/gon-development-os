# 작업 수행과 재개

이 문서의 원격 생성·갱신은 요청 또는 프로젝트에서 허용한 범위에만 적용한다. 그 밖에는 로컬 초안을 `pending_sync`로 남긴다.

## 재개할 때 현재 사실을 복구한다

관리 문서에 연결된 GitHub 이슈·Project·PR/CI를 현재 원격에서 읽고 로컬 요약과 대조한다. 현재 branch/revision, 미커밋 diff, 관련 코드·검사를 필요한 만큼 확인한다. 기록이 오래됐다는 이유만으로 전부 다시 검증하지 않는다. 수정한 부분·실패한 검사·근거가 없어진 조건에 맞춰 확인한다.

다음 중 무엇이 남았는지 정하고 그 지점에서 이어간다: 범위 결정, 구현, 검증 실패 해결, 리뷰 지적, 전달/배포. `진행 중` 또는 PR 생성 상태를 완료로 해석하지 않는다. 다른 사람이 만든 미완성 변경을 되돌리거나 내 변경으로 기록하지 않는다.

착수 전부터 존재한 실패는 기준선으로 남기고 이번 변경의 회귀와 구분한다. 기존 미커밋 변경이 이번에 이어갈 작업인지 무관한 작업인지 diff와 요청으로 판단한다. 범위 밖의 기존 실패는 요청을 확대해 고치지 말고 영향과 함께 보고한다.

## 작업을 관찰 가능한 단위로 만든다

다중 파일 기능·구조 변경과 재현 가능한 버그는 아래 내용을 GitHub 이슈에 담고 Project에 연결한다. AEOS TASK를 쓰면 이슈에는 요약·계약 경로와 revision만 연결해 중복 수정을 피한다. 작은 수정은 기존 이슈/PR에 연결하며 별도 이슈를 강제하지 않는다. 원격 접근이 없으면 계약/로컬 초안으로 진행하되 `pending_sync`로 남긴다.

- 목표와 수용 기준: 어떤 입력·행동에서 어떤 결과를 확인할 것인가.
- 허용 변경과 제외 범위, 필요한 선행 결정.
- 재현/검사 방법, 실제 제품 환경과 알려진 한계.
- 여러 작업자가 승인된 경우 파일/책임 소유권과 통합 담당자.

버그는 실패 조건을 먼저 확인한다. 새 기능은 현재 구조에 맞는 가장 작은 변경부터 만든다. 소유권이 겹치거나 선행 결과가 필요한 작업을 억지로 병렬화하지 않는다.

## 구현과 검증을 연결한다

실제 프로젝트의 패키지 관리자·잠금 파일·CI 명령을 유지한다. 필요한 제품 동작을 구현하고 변경에 맞는 검사를 실행한다. 사소한 문구 변경을 위해 테스트 체계를 만들지 않는다. 실패한 테스트 삭제나 검증 완화를 해결로 기록하지 않는다.

증거에는 검사 대상 revision(미커밋 변경이면 그 사실), 환경, 명령, 결과와 필요한 로그/화면 경로를 남긴다. 비밀값은 제외한다.

| 상태 | 기록 기준 |
| --- | --- |
| `PASS` | 실제 실행·관찰한 조건을 충족 |
| `FAIL` | 실행했고 기준을 충족하지 못함 |
| `NOT_RUN` | 실행하지 못했거나 실행하지 않음. 이유와 영향 기록 |
| `UNKNOWN` | 관찰만으로 판정할 수 없음. 필요한 다음 확인 기록 |

종료 코드 0·HTTP 200·설정 저장만으로 사용자 흐름 성공을 주장하지 않는다. 웹 UI는 필요한 경우 현재 사용 가능한 브라우저 도구로 관련 흐름·상태를 확인하고, 로그인·운영 환경 접근 범위도 기록한다.

실패하면 원인과 바꿀 가설을 정한 뒤 의미 있는 수정·재검사를 한다. 같은 원인의 반복 실패는 적용 지침의 재시도 한도를 지키고 남은 조건을 보고한다. 지연·할당량을 이유로 모델이나 제공자를 자동 대체하지 않는다.

한도가 정해져 있지 않아도 같은 가설을 반복하지 않는다. 가설을 바꾼 시도에서도 같은 외부 차단이 계속되고 독립적으로 진행할 일이 없으면 필요한 조건과 증거를 보고한다.

## 상태를 짧게 갱신한다

의미 있는 단계 전환에서 기준 GitHub 이슈와 Project의 기존 상태를 갱신한다. 완료한 작업, 검사 대상 SHA·CI/증거 URL, 남은 실패, 다음 행동·책임자만 남긴다. 상태·본문을 쓰기 직전에 다시 읽고 다른 사람의 편집을 보존한다. 기존 관리 영역/댓글만 갱신해 재실행마다 댓글·이슈를 늘리지 않는다.

원격 재조회로 저장과 상태를 확인한 후 로컬 STATE에는 URL과 확인 시점만 요약한다. 메모리/작업 추적 도구가 필수인 환경에서는 GitHub 링크를 가진 보조 기록으로 사용한다. 결과가 생기기 전에 PASS·Done을 채우지 않는다. 원격 기록이 실패하면 `pending_sync`와 실패 범위를 남기고 독립적인 제품 작업을 계속한다.

완료 경계의 검토와 전달은 [delivery.md](delivery.md)를 따른다.
