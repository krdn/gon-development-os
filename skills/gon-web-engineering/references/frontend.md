# 프런트엔드 지침

읽을 때: React, TypeScript, 화면 상태, 라우팅, 스타일, 브라우저 SDK를 구현·수정·분석할 때.

## 구현

- 신규 기본 조합은 React + TypeScript + React Router Framework Mode(Vite 기반)이다. 기존 프로젝트의 확정된 조합과 스타일을 따른다.
- TypeScript strict 검사를 사용한다. 오류를 감추기 위한 무분별한 any, 타입 단언, 검사 비활성화를 피한다. 동적 경계는 실제 입력 검증과 의미 있는 타입으로 좁힌다.
- 컴포넌트와 화면 상태를 작게 나누고, 계산·검증 같은 순수 로직은 UI 생명주기와 분리한다.
- 라우터의 데이터 조회·변경 방식을 일관되게 사용한다. 별도 캐시나 상태 관리 도구는 해결할 문제가 명확할 때 추가한다.
- 로딩, 빈 결과, 입력 오류, 권한 부족, 요청 실패, 재시도 가능 상태를 제품 요구에 맞춰 구현한다.
- 키보드 조작, 포커스, 의미 있는 HTML, 작은 화면에서의 배치를 확인한다.

## 렌더링과 브라우저 경계

- 로그인 중심 업무 UI는 SPA를 기본으로 한다. 공개 콘텐츠·SSR 요구가 있으면 아키텍처 결정을 함께 확인한다.
- React Router SPA 모드도 빌드 시 초기 렌더링을 수행한다. window, localStorage 등 브라우저 전용 API의 실행 시점을 구분한다.
- 요청 취소, 오래된 응답, 중복 제출이 화면과 서버 상태에 미치는 영향을 확인한다.
- 외부 SDK의 초기화, 이벤트 등록, 정리, 오류 변환을 연결 모듈에 모은다.
- UI 프레임워크와 외부 SDK가 같은 DOM이나 상태를 동시에 관리하지 않도록 책임을 정한다.

## UI 부품

기존 디자인 체계를 우선한다. 신규 업무형 UI에서는 MUI를 검토하되, 필요한 기능·번들 크기·사용 조건을 확인한다. MUI X의 고급 기능은 상용 라이선스가 필요할 수 있다. 컴포넌트를 사용하더라도 실제 제품의 접근성과 동작은 검증한다.

## API

- 서버 OpenAPI에서 생성한 타입과 정해진 API 클라이언트를 사용한다. 생성 파일은 직접 수정하지 않고 원본 계약과 생성 과정을 수정한다.
- API 계약을 변경한다면 프로젝트의 API 지침을 읽는다. 이 스킬에서는 `references/backend-data.md`를 선택한다. 프로젝트에 해당 문서가 복사되어 있으면 같은 폴더의 `backend-data.md`를 사용한다. 파일이 없으면 스킬 원본을 확인하며, 화면 전용 작업 때문에 서버 지침을 설치하지 않는다.
- 생성된 타입을 런타임 검증으로 간주하지 않는다. 외부 데이터의 형태와 실패 처리에 필요한 검증을 둔다.
- 서버 권한과 최종 업무 규칙을 브라우저의 조건문만으로 구현하지 않는다.
- 날짜, 금액, 식별자의 전송 계약을 유지하고 표시 형식과 저장 형식을 구분한다.

## 검증

동작을 바꾸는 작업은 프로젝트의 검증 지침을 함께 적용한다. 복사된 `verification.md`가 없으면 스킬의 `references/verification.md`를 사용한다. 실제 저장소의 TypeScript 검사와 프런트엔드 빌드를 실행하고, 변경한 사용자 흐름을 브라우저에서 확인한다. 검사 범위는 변경 영향에 맞춘다.
