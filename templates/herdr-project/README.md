# Herdr 프로젝트 시작 방법

처음 실행한다면 [Herdr CLI 시작 가이드](../../docs/06-herdr-cli-start.md)의 로컬·원격 Space 선택부터 따라갑니다.

아이디어를 작성하고 주 모델에게 실행 문서를 읽히면, 주 모델이 기획 → 조사 → 설계 → 구현 → 검증 → 인계를 진행하며 필요한 협업 모델을 Herdr에 엽니다. 사용자에게 필요한 질문과 협업 모델에게 맡길 기술 질문을 구분합니다.

## 1 문서를 프로젝트 폴더에 넣기

이 폴더의 `HERDR-PROJECT.md`와 `HERDR-OPERATIONS.md`를 실제 프로젝트 폴더에 복사합니다. 기존 파일이 있으면 덮어쓰지 말고 내용을 비교합니다. `HERDR-PROJECT.md`의 **사용자 입력**에서 아이디어를 작성합니다. 나머지는 기본값으로 시작할 수 있습니다.

아직 프로젝트 폴더가 없다면 원하는 이름의 빈 폴더를 먼저 만듭니다. 이 안내서 폴더에서 제품을 개발하지 않습니다.

## 2 Herdr에서 시작하기

주 모델의 도구 환경에서 `herdr-app ls`, `herdr-app status`, `herdr-core get` 접근을 확인합니다. 일반 쉘의 성공만으로 판단하지 않습니다. 샌드박스가 막으면 공식 권한 절차로 필요한 접근을 마련하고 다시 확인합니다. 승인 기록만으로 협업 성공으로 표시하지 않습니다.

Herdr에서 해당 폴더의 터미널을 엽니다. 쉘에서 아래 명령을 실행합니다. 경로는 실제 프로젝트 절대경로로 바꿉니다.

```sh
codex --no-daemon -C '/실제/프로젝트/절대경로' -m gpt-6-astra -c model_reasoning_effort='"xhigh"'
```

이는 2026년 11월 3일 확인된 로컬 운영 후보입니다. 실행 시 모델 지원 오류가 있으면 다른 모델로 몰래 바꾸지 말고 사용 가능한 목록과 프로젝트의 모델 정책을 먼저 확인합니다. 로그인·권한 문제가 있으면 해당 CLI가 제공하는 사용자 인증 절차를 완료합니다.

**Codex의 대화 입력칸**에 아래 요청을 한 번 넣습니다. 쉘에 넣는 명령이 아닙니다.

```text
이 프로젝트의 HERDR-PROJECT.md와 HERDR-OPERATIONS.md를 실제로 읽고 실행해.
너는 주 실행 책임자야. 사용자 입력과 기존 지침을 기준으로 기획부터 선택한 완료 목표까지 진행해.
필요한 독립 작업은 적합한 협업 모델을 선택해 Herdr 분할 터미널 또는 이름 있는 탭에서 수행시켜.
기술 질문은 조사·실험·협업 모델의 답변으로 해결하고 결과를 검증해 통합해.
사용자만 답할 수 있는 결정은 필요한 질문만 모아서 물어보고, 독립 작업은 계속해.
계획이나 문서 작성만으로 끝내지 말고 실제 구현·실행·검증과 최종 인계까지 진행해.
먼저 작업 경로, 아이디어, 권한, 사용 가능한 모델·Herdr 제어 기능을 확인하고 첫 작업을 시작해.
```

이미 Herdr에서 Codex가 실행 중이라면 같은 프로젝트인지, `--no-daemon`으로 실행되어 Herdr 터미널 안에서 도구가 동작하는지 확인한 뒤 요청을 넣습니다. 다른 프로젝트의 실행 중인 대화에 넣지 않습니다.

## 3 질문에 답하고 결과 확인하기

기본 완료 목표는 **로컬에서 핵심 사용자 흐름이 동작하고 검증·인계 문서가 남은 상태**입니다. GitHub 저장·통합·운영 배포까지 원하면 입력란에 대상과 허용 행동을 적습니다. 주 모델은 이미 허용한 행동을 단계마다 다시 묻지 않습니다.

한번 시작한 대화가 종료되거나 PC가 재시작되면 자동으로 계속된다고 가정하지 않습니다. 같은 폴더의 새 주 모델에 다음을 입력합니다.

```text
HERDR-PROJECT.md, HERDR-OPERATIONS.md와 docs/STATE.md를 읽고 중단 지점부터 재개해.
실제 Git 변경·기존 Herdr 작업자·저장된 결과를 먼저 대조해 중복 실행을 막아.
이전 권한과 모델 선택을 보존하고, 완료되지 않은 첫 작업을 수행해.
```

이 묶음은 에이전트가 읽고 수행하는 실행 계약입니다. 상주 스케줄러나 자동 복구 서비스는 설치하지 않습니다. 모델·계정·도구 권한, 사람의 필수 답변과 실행 중인 주 모델이 있어야 전체 흐름을 계속할 수 있습니다. 모든 프로젝트의 무결함·무중단 완료를 보장하지 않습니다.

## 문서 구성

- [HERDR-PROJECT.md](HERDR-PROJECT.md): 아이디어 입력과 처음부터 끝까지의 실행 규칙.
- [HERDR-OPERATIONS.md](HERDR-OPERATIONS.md): 실제 Herdr 명령, 협업 지시·결과·상태 양식.
- [VERIFICATION.md](VERIFICATION.md): 확인한 기능과 실제 프로젝트 실행 검증의 구분.

기존 안내서의 P1~P5와 개발 01~10 흐름을 이어받습니다. 이번 문서는 별도 실행 양식이며 기존 안내서·앱 설정·설치 스킬을 변경하지 않습니다.
