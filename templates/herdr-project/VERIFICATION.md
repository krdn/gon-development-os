# 실행 양식의 검증 범위

이 양식은 Herdr에서 주 모델이 읽고 수행하는 문서 계약이다. 파일 자체가 상주 실행기나 자동 복구 서비스는 아니다.

2026년 11월 3일 작성 시 설치된 Herdr app 0.1.12/core 0.1.17 도움말과 명령 구조를 대조했다. 현재 기기의 버전·모델 목록·권한·terminal/pane ID는 실행 시 다시 확인한다. 이번 협업 시험은 Codex 0.167.0을 `--no-daemon`으로 실제 시작해 도구가 Herdr 터미널에서 동작하는 범위를 확인했다. 시작 안내의 같은 옵션과 resume 구문은 현재 CLI 도움말로 대조했으며 resume 자체는 실행하지 않았다. 주 모델 내부에서 앱/core 접근과 첫 요청 수신을 확인해야 하며, 외부 쉘에서의 성공만으로 추정하지 않는다.

별도 OCR 예시의 과거 시험은 문서 읽기와 결과 저장까지 성공했지만 협업 실행이 접근 권한으로 차단됐다. 이 양식을 사용하면 모든 프로젝트가 자동 완료된다는 검증은 하지 않았다. 모델 응답·결과 저장·통합·제품 동작·배포를 각각 확인한다.

현재 저장소의 빌드는 문서 링크와 파일 무결성을 검사한다. 서버가 적용한 실제 모델·effort, 사용자 데이터의 OCR 정확도, 운영 배포는 별도 검증 대상이다. CLI 승인 생략 옵션은 실행 계약의 명령에 명시하며 계정·OS·서비스 접근은 실제 실행 결과로 확인한다.

## 2.1.0 전문가 협업 시험

2026-11-09 Herdr app 0.1.14/core 0.1.19에서 별도 시험 공간·이름 있는 작업자 터미널을 사용했다. Opus 리뷰어가 명세·보정 예제를 읽고 결함을 지적했고, 총괄이 보완한 명세를 다시 검토했다. 후보는 합성 자료의 정상·모호·상충 3과제와 새 세션의 대표 과제를 수행했다. 실제 반론 파일을 전달하고 두 후보 세션의 응답·수정을 회수했다. 새 개발 세션이 BRIEF·STATE를 읽고 범위·첫 작업·AC·미정을 회신한 것도 확인했다.

최초 시험의 전문가 절은 당시 원본과 바이트가 일치했다. 리뷰 후 채점 정의·총괄 미달·동시 수 규칙을 보완했으므로 최초 점수를 새 기준의 현재 자격으로 재사용하지 않는다. 보존한 최초 사용자 입력 세션을 포함하면 한때 CLI가 최대 3개여서 당시 시험은 동시 상한을 충족하지 못했다. 이 한계와 보존 세션을 포함한 추가 시험은 검증 기록에 구분한다. 메시지 전달에서는 done 상태가 `send --if idle`과 일치하지 않아 입력이 거절되는 경우를 확인했고, 실제 완료·미입력 상태를 확인한 뒤 일반 send를 사용하도록 설명을 보완했다. 사용자 입력이 시작된 시험용 칸은 보존하고 이후 자동 시험은 별도 터미널에서 수행했다.

개별 평가 판정·입력/결과 식별값·실제 모델 확인 범위·빌드·외부 리뷰는 [검증 기록](../../evidence/expert-planning-validation.json)을 따른다. 이 시험은 쉬운 합성 과제의 협업 절차를 확인한 것이다. 실제 산업 전문성·외부 백분위·모든 프로젝트의 에이전트 품질을 입증하지 않는다. 총괄의 4회 역량 평가, 리뷰어의 복잡한 분야 판정, 실제 제품 AC 실행, 개발 주 모델 소유권 전환·구현·배포는 이 시험에서 검증하지 않았다. 모델이 읽는 계약이며 Herdr 명령 자체의 강제 차단기를 설치한 것은 아니다.

## 1.4.1 스킬 통합 검토

[Opus 검토와 지적 처리 기록](../../evidence/herdr-skill-integration-review.json)에 단계별 스킬 선택, P5 인수 회신, 작업자 역할·결과 기록, 미설치와 구버전 문서 재개의 검토 범위를 남겼다. 전문 스킬의 원본과 호출 정책은 `skills.lock`의 버전을 따른다.

두 실행 문서를 읽은 주 모델이 단계별 규칙을 수행하도록 문서로 연결했다. 실제 세션에서의 지침 읽기·적용은 STATE나 작업 결과의 경로·참조·작업 근거로 확인한다. 이번 문서 재생성과 정적 리뷰로 여러 세션의 인계나 실제 웹 구현을 실행 검증했다고 판정하지 않는다.
