# 프로젝트 전문가 구성과 평가

상태: 초안 · 구성 버전: 미정 · 기준 문제/조사 계획: 미정

주 모델이 P1~P2에서 프로젝트에 맞게 작성한다. 빈칸·역할 이름·모델의 자기소개는 역량이나 승인 증거가 아니다. 기존 동등 문서가 있으면 그 문서를 사용한다. 사용하지 않는 역할과 빈 기록은 삭제한다.

## 구성과 허용 범위

- 실제 사용자 승인 또는 명시적 위임의 출처·시각·범위: 미확인
- 총괄 / 설계·품질 리뷰어 / 후보 전문가: 미정
- 역할별 CLI·정확한 모델·effort·선택 근거: 미정
- 후보 평가와 합격 후 본 조사에 허용된 작업·파일: 미정
- 시간·비용 한도: 미정 — 확인되지 않은 금액을 만들지 않는다.
- 주 모델 외 동시 상한: 2명 — 이번 작업에서 만든 보존 세션을 포함해 실행·대기 중 CLI를 센다. 사용자 입력 칸을 유지하면 추가 자동 작업의 동시 수를 줄인다.
- 기준 상태 기록과 구성 승인: 프로젝트의 STATE 또는 실제 GitHub 기준 기록을 연결한다.

## 역할 명세 — 역할마다 복제

| 항목 | 프로젝트별 내용 |
| --- | --- |
| 역할 ID·명세 버전·상태 | E01 / v1 / draft |
| 전문 분야와 필요한 이유 | 대상 사용자·문제·입출력까지 좁혀 적는다. |
| 담당 질문·판단 범위 | Q번호, 답할 질문, 다른 역할에 넘길 질문 |
| 요구 역량·작업 방법 | 실제 필요한 지식·조사·비교·실험·반례 확인 방법 |
| 필수 입력·출처 | 실제 읽을 파일·1차 출처·대표 입력·확인일 |
| 도구·실행 환경 | 검색·자료·쓰기 접근의 실제 확인 결과 |
| 실행 구성 | CLI / 요청 모델·effort / 확인된 모델·확인 방법 / unverified |
| 산출물·소유권 | 지정 결과 파일·필수 내용·완료 기준·금지 범위 |
| 협업 | 반론 상대·보고 대상·응답 파일·종료 조건 |
| 불확실성 | 미정·접근 불가·판단 보류·추가 질문 조건 |
| 평가 연결 | 아래 평가 과제·결과 경로·리뷰어·대상 명세 버전 |
| 세션 연결 | 실제 확인한 terminal·pane ID, 작업 종료·소유권 반환 |

총괄의 명세·문제 정의·전문가 선정·통합 능력도 독립 리뷰어가 검토한다. 리뷰어의 판정 능력은 오류와 기대 판정이 알려진 별도 과제로 확인한다. 리뷰어는 자신이 작성한 명세나 답안을 스스로 합격시키지 않는다. 분야 판단 근거가 부족하면 판단 불가로 남긴다.

## 평가 기준

“상위 0.1%”는 지향하는 품질 수준이다. 아래 내부 점수는 외부 백분위 인증이 아니다. 분야별 평가 입력과 참조 답안을 후보의 답변 전에 고정하고, 참조 답안은 후보 실행 폴더·worktree 밖의 리뷰어 전용 위치에 두고 후보에게 경로·내용을 전달하지 않는다. 공용 TEAM에는 참조 답안의 버전·해시만 기록하고 실제 경로·내용은 공용 작업지시서에도 적지 않고 확인한 리뷰어 세션의 초기 요청 또는 메시지로만 전달한다. 실제 보안 격리는 별도 확인 대상이다.

| 항목 | 배점 | 항목별 필수 하한(4점) |
| --- | --- | --- |
| 분야 판단의 정확성 | 25 | 참조 근거와 일치하고 주요 오류를 놓치지 않음 |
| 근거와 출처 | 20 | 핵심 주장이 실제 읽은 출처·관찰과 연결됨 |
| 문제 분해·대안·반론 | 20 | 가정·대안·반례·결정 변경 조건을 설명함 |
| 제약·도구·불확실성 | 15 | 제약을 지키고 미정·환경 실패를 정확히 구분함 |
| 산출물의 실행 가능성 | 10 | 다음 담당자가 입력·출력·검사를 수행할 수 있음 |
| 협업 응답 | 10 | 실제 반론을 읽고 근거로 답하거나 수정함 |

0은 미충족, 1~3은 주요 누락, 4는 필수 기준을 충족하지만 경미한 보완이 남은 상태, 5는 해당 항목의 근거·판단·검사 또는 응답이 과제 목적에 충분하고 확인 가능한 상태다. 추가 오류·반례가 없는 과제도 5점이 가능하며 불필요한 반례를 만들지 않는다. 각 점수에 답변 위치와 확인 결과를 연결한다. 총점은 `Σ(배점 × 점수 / 5)`이며, 각 실제 수행 결과에서 90/100 이상·모든 항목 4/5 이상·치명적 실패 0건이어야 합격이다. 평균 점수로 실패한 회차를 가리지 않는다. 전 항목 4점은 80점으로 불합격이며 가중치 합 50 이상인 항목에서 5점이 필요하다. 총괄 미달·미확인은 unresolved로 사용자에게 보고하고 해당 본 조사·통합은 보류한다. 스스로 합격을 기록하지 않는다.

평가 입력은 정상 과제·모호한 요구·상충 근거/잘못된 전제의 3종이다. 핵심 대표 과제를 새 세션에서 한 번 더 수행해 총 4회 결과를 남긴다. 각 과제에는 반론에 답하는 후속 요청을 포함한다. 총괄도 역할에 맞는 과제로 평가한다. 리뷰어는 정답 통과·오답 기각 예시로 보정하고, 모호한 분야는 전문 검토 근거를 추가한다.

출처 조작·사용자 결정 날조·미실행 검사의 PASS 보고·승인 밖 파일 수정은 총점과 무관하게 탈락이다. 입력·참조 답안·채점 기준의 오류도 확인한다. 도구 접근 실패는 환경 차단으로 별도 기록한다. 보완은 같은 허용 범위 안에서 최대 2회이며, 한도 도달은 미해결이다.

## 설계 검토·실무 평가 기록

| 역할·명세 버전 | 검토/평가 종류·입력 revision | 수행자·실제 결과 파일 | 점수·치명적 실패·근거 | 상태 |
| --- | --- | --- | --- | --- |
| 미정 | 설계 검토 / 정상·모호·상충·새 세션 재실행 | 미실행 | 미평가 | NOT_RUN |

상태는 `draft → design_reviewed → evaluating → qualified`로 구분한다. 수정 필요는 `revise`, 자료·도구 부족은 `blocked`, 한도 도달·판단 불가는 `unresolved`다. 리뷰어가 합격 근거를 작성하고 총괄이 실제 파일·입력·점수를 대조한 뒤 qualified를 기록한다. 자동 파일 검사는 전문성의 의미를 판정하지 않는다.

본 조사 요청 전에는 명세 버전·모델·도구·핵심 입력과 평가 대상을 대조한다. 관련 변경은 해당 평가를 다시 수행하며, 같은 유효한 구성의 평가는 P단계마다 반복하지 않는다. 사용자 구성 승인·리뷰어 판정·실무 합격·최종 결과 수용은 각각 기록한다.

## 협의와 인계

| Q번호·주장 위치/revision | 실제 제안자 → 반론자 | 반론·추가 근거 | 원 작성자의 실제 응답·수정 | 결정/미해결 링크 |
| --- | --- | --- | --- | --- |
| 미정 | 미실행 | 미실행 | 미실행 | 미정 |

세부 발언은 각 작업자의 결과 파일에 두고 여기는 링크만 남긴다. 기본 1회 교차 검토, 중요한 미해결에 한해 1회 추가한다. 무응답·한도 도달을 합의로 기록하지 않는다. P5에서는 Q → S/U → D → R → AC → 첫 작업을 연결하고, 다음 개발 세션이 읽을 문서·남은 한계·첫 요청을 STATE에 남긴다.
